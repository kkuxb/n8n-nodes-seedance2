# Phase 14: 多模态入口与参考材料表单 - Context

**Gathered:** 2026-05-19
**Status:** Ready for planning

<domain>
## Phase Boundary

This phase adds the user-facing entry point and n8n parameter form for official Seedance 2.0 "多模态参考生视频" inside the existing `Seedance` video `create` operation. It clarifies how users select the mode and configure repeatable reference inputs. Payload normalization, full media validation, lifecycle compatibility, and user documentation remain in later phases unless a minimal placeholder is required to keep the form coherent.

</domain>

<decisions>
## Implementation Decisions

### 创建模式入口与命名
- **D-01:** Add a fourth `createMode` option named **多模态参考生视频**.
- **D-02:** Keep the existing option order first: 文生视频, 首帧图生视频, 首尾帧图生视频. Add 多模态参考生视频 after 首尾帧图生视频.
- **D-03:** Keep the default create mode as 文生视频 (`t2v`) so existing user behavior does not change.
- **D-04:** Reuse the existing **提示词** field for multimodal mode. In multimodal mode it is optional; do not add a separate multimodal prompt field.
- **D-05:** Keep the create-mode option description concise: describe it as the official multimodal reference video mode using reference image/video/audio plus optional prompt. Do not put all restrictions in the option description.

### 参考素材表单
- **D-06:** Use one unified repeatable list named **参考素材**. Do not use the previous wording "参考材料" in user-facing form text.
- **D-07:** Each reference item has these fields in order: **素材类型**, **素材来源**, then the source-specific value field. Do not include a label, name, tag, or note field.
- **D-08:** The **素材类型** field has 图片, 视频, 音频. New items default to 图片.
- **D-09:** The **素材来源** field defaults to **URL链接**.
- **D-10:** The source options are named **URL链接**, **Binary文件**, and **火山方舟素材库**.
- **D-11:** The source-specific value fields are named **素材URL** for URL链接, **属性名** for Binary文件, and **素材ID** for 火山方舟素材库.
- **D-12:** Phase 14 allows the 参考素材 list to be empty. Combination rules, audio-only rejection, media counts, and size/format validation belong to Phase 16.

### 来源显示边界
- **D-13:** 图片素材 supports URL链接, Binary文件, and 火山方舟素材库.
- **D-14:** 视频素材 supports URL链接 and 火山方舟素材库 only. Do not offer Binary文件 for video.
- **D-15:** 音频素材 supports URL链接, Binary文件, and 火山方舟素材库.
- **D-16:** Do not expose direct Base64 text input as a Phase 14 source option. For image/audio, Binary文件 can later be converted to data URL/Base64 by implementation phases.
- **D-17:** For 火山方舟素材库, the **素材ID** field accepts either a bare asset ID or a full `asset://...` URI. Phase 15 normalizes the value to official `asset://<ASSET_ID>` form.
- **D-18:** The **属性名** field description must clearly say it is the n8n input item's binary property name, defaulting to `data`; it is not a file upload control.

### 用户提示文案
- **D-19:** Only add explicit guidance for real-person face reference restrictions. Do not add extra warnings for multimodal vs first-frame/last-frame mutual exclusion because `createMode` is already a single-select field.
- **D-20:** Do not add special guidance saying advanced options are optional. Keep advanced options as optional controls.
- **D-21:** The real-person face restriction text must state that Seedance 2.0 currently accepts real-face reference material only from two sources: material generated by Seedream 5.0 Lite text-to-image, and 火山方舟素材库.
- **D-22:** Place this face restriction guidance in image-related value field descriptions: existing first-frame/last-frame image URL and binary-property fields, plus multimodal image **素材URL**, **属性名**, and **素材ID** fields. Do not add a separate global notice field for this.

### Requirement Change
- **D-23:** Cancel the label/tag field even though the current ROADMAP success criteria and `UI-01` mention adding labels. The user decided it has no practical value because it is not passed as an API parameter. Before planning or verification, update or explicitly reconcile `.planning/ROADMAP.md` and `.planning/REQUIREMENTS.md` so Phase 14 is not judged against a removed label requirement.

### the agent's Discretion
- No user-facing behavior was left to the agent's discretion. Planner/researcher may choose the exact internal TypeScript names and helper boundaries as long as the user-facing names and behavior above are preserved.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `nodes/Seedance/description/image.operation.ts` already uses `fixedCollection` with `multipleValues: true`; reuse that shape for the **参考素材** list.
- `nodes/Seedance/Seedance.node.ts` already has binary image helpers and `getNodeParameter` collection patterns that can guide later source collection.
- `nodes/Seedance/shared/mappers/createPayload.ts` already maps prompt and first/last-frame images into official `content` items; later phases can extend this for reference image/video/audio content.

### Established Patterns
- UI property descriptions live in `nodes/Seedance/description/*.operation.ts`, with `displayOptions` controlling mode-specific visibility.
- User-facing validation errors are Chinese plain `Error` / `NodeOperationError` messages.
- Tests import compiled `dist` JavaScript, so implementation plans should include build-before-test steps when adding tests.

### Integration Points
- Extend `createMode` in `nodes/Seedance/description/create.operation.ts` and the corresponding type in `nodes/Seedance/shared/validators/create.ts`.
- Add multimodal-only form fields under the video create operation display options.
- Later phases should connect collected reference materials to `SeedanceCreateInput`, `buildCreatePayload`, and request summary output.

</code_context>
