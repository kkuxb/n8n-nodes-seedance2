# Plan 17-02: Lock task lifecycle, wait, and download compatibility

<objective>
Protect the shipped task lifecycle behavior for old and multimodal video tasks by adding execute-level checks for get/list/delete plus wait/download terminal outcomes and attachment rules.
</objective>

<scope>
In scope:
- Immediate get execution contract.
- List execution query/filter/pagination and aggregated output contract.
- Delete execution path and success envelope.
- Wait succeeded, failed, and timeout behavior.
- Download attachment and non-attachment conditions.
- Runtime fixes only if tests expose a real compatibility regression.

Out of scope:
- Exhaustive friendly-error branch expansion for list/delete.
- New lifecycle capabilities.
- Manual provider API testing.
- Documentation updates.
</scope>

<threat_model>
| ID | Threat | Severity | Mitigation |
|----|--------|----------|------------|
| T-17-05 | Get/list/delete mapper tests pass while node request options regress. | high | Capture execute-level method/path/query/output for each operation. |
| T-17-06 | List filters or pagination change silently. | high | Assert `filter.status`, `filter.task_ids`, `filter.model`, `filter.service_tier`, `page_num`, and `page_size`. |
| T-17-07 | Download triggers on failed/timeout/no-url tasks. | high | Add non-attachment tests with call-count checks. |
| T-17-08 | Wait behavior works for old task response but not multimodal task response. | medium | Use representative old and multimodal task response shapes through the same execution path. |
</threat_model>
