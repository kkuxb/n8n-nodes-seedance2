# Plan 17-03: Lock Seedream image isolation and full regression

<objective>
Prove that Seedream image generation remains isolated from the new video multimodal helpers, while preserving the existing image execution behaviors and completing full Phase 17 regression.
</objective>

<scope>
In scope:
- Execute-level image isolation tests.
- Existing Seedream image behavior regression coverage.
- Description-level image operation contract only if needed.
- Final full test-suite verification.
- Runtime fixes only if tests expose a real regression.

Out of scope:
- New Seedream features.
- New image UI options.
- Manual image generation against the live provider.
- User documentation.
</scope>

<threat_model>
| ID | Threat | Severity | Mitigation |
|----|--------|----------|------------|
| T-17-09 | Image mode starts reading hidden video parameters from saved workflows. | high | Add a fake context that throws on video-only parameter reads. |
| T-17-10 | Video multimodal helper refactors alter Seedream payload/output. | high | Preserve existing prompt-only, image-to-image, grouped, and binary output tests. |
| T-17-11 | Phase 17 accidentally changes image user behavior while adding tests. | medium | Treat runtime edits as bug fixes only; no new Seedream fields or behavior. |
| T-17-12 | Focused tests pass but another regression exists elsewhere. | medium | Run the full `node --test test/*.test.ts` suite after focused image tests. |
</threat_model>
