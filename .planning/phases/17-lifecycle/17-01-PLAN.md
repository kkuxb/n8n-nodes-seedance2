# Plan 17-01: Lock old video create payload compatibility

<objective>
Prove that the three shipped video create modes still submit the same provider payloads after the multimodal work, including saved-workflow cases with stale hidden multimodal fields.
</objective>

<scope>
In scope:
- Execute-level tests for `t2v`, `i2v_first`, and `i2v_first_last`.
- Captured HTTP body assertions for content items, roles, model, prompt, and generation options already covered by the create branch.
- Negative assertions that old modes do not read or emit multimodal references.
- Small runtime fixes only if a test exposes a real regression.

Out of scope:
- New multimodal behavior.
- Lifecycle get/list/delete behavior; Plan 17-02 owns that.
- Seedream image behavior; Plan 17-03 owns that.
- User documentation or manual UAT.
</scope>

<threat_model>
| ID | Threat | Severity | Mitigation |
|----|--------|----------|------------|
| T-17-01 | Old create tests pass even though HTTP body changed. | high | Assert exact captured request body from `Seedance.prototype.execute.call(context)`. |
| T-17-02 | Stale saved-workflow `referenceMaterials` pollutes old modes. | high | Include stale multimodal fields and assert no `reference_*` role appears. |
| T-17-03 | First/last-frame modes lose strict frame roles. | high | Assert `first_frame` and `last_frame` roles exactly. |
| T-17-04 | Test setup becomes too broad and duplicates payload-unit coverage. | medium | Keep this plan focused on execute-level old mode contracts only. |
</threat_model>
