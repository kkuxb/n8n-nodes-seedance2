# Plan 15-02: Wire n8n reference source collection into multimodal create execution

<objective>
Connect the Phase 14 `参考素材` form to the Phase 15 shared payload contract inside `Seedance.execute()`, including URL, asset, and image/audio binary sources, while preserving existing video create behavior and adding execute-level HTTP body regression coverage.
</objective>

<scope>
In scope:
- Runtime collection of multimodal reference rows from `referenceMaterials`.
- Binary image/audio conversion to official data URL strings using n8n binary MIME.
- Execute-level tests proving captured create-task HTTP body and safe summary output.

Out of scope:
- UI field changes.
- Video binary source support.
- Phase 16 format, size, duration, FPS, codec, and total request-size validation.
- Live Volcengine API calls.
</scope>

<threat_model>
| ID | Threat | Severity | Mitigation |
|----|--------|----------|------------|
| T-15-04 | Binary data or private media source values leak into returned `requestSummary`. | high | Execute-level tests inspect output JSON and reject raw URL, Base64, binary property, and asset ID substrings. |
| T-15-05 | Binary reference collection reads first/last-frame parameters or video binary paths in multimodal mode. | medium | Regression tests assert no first/last-frame parameter reads and no video binary helper use. |
| T-15-06 | Empty rows are silently dropped during node parameter collection, changing user order. | medium | Collector throws a `NodeOperationError` or plain error that is normalized by the existing execute catch path; tests cover empty active source field. |
</threat_model>

<tasks>
<task id="15-02-01" type="execute">
<title>Make multimodal reference collection async and strict</title>
<read_first>
- nodes/Seedance/Seedance.node.ts
- nodes/Seedance/shared/validators/create.ts
- .planning/phases/15-payload/15-CONTEXT.md
- .planning/phases/15-payload/15-PATTERNS.md
</read_first>
<action>
Change `collectSeedanceReferenceMaterials` into an async collector used only when `createMode === "multimodal_reference"`. For each configured `referenceMaterials.items` row, resolve `materialType`, active source field, and active value field from the existing Phase 14 field names: `materialUrl`, `videoMaterialUrl`, `assetId`, `videoAssetId`, and `binaryProperty`. If a row exists and the active value is empty after trim, throw a clear Chinese error naming `参考素材`. Preserve configured row order.
</action>
<acceptance_criteria>
- `Seedance.node.ts` awaits the multimodal reference collector before calling `buildCreatePayload()`.
- Existing first-frame and last-frame parameter reads remain guarded by `createMode === "i2v_first"` or `createMode === "i2v_first_last"`.
- A configured multimodal row with empty `materialUrl`, `videoMaterialUrl`, `assetId`, `videoAssetId`, or `binaryProperty` causes execution to reject before HTTP request.
</acceptance_criteria>
</task>

<task id="15-02-02" type="execute">
<title>Convert image/audio binary references to official data URLs</title>
<read_first>
- nodes/Seedance/Seedance.node.ts
- nodes/Seedance/shared/validators/create.ts
- nodes/Seedance/shared/mappers/createPayload.ts
- .planning/phases/15-payload/15-RESEARCH.md
</read_first>
<action>
For image and audio references with `materialSource === "binary"`, call `this.helpers.assertBinaryData(itemIndex, binaryProperty)`, read `items[itemIndex].binary?.[binaryProperty]?.mimeType`, require a non-empty MIME type, call `this.helpers.getBinaryDataBuffer(itemIndex, binaryProperty)`, and set the reference value to `data:<mime>;base64,<buffer.toString("base64")>`. Do not add MIME allowlists or size checks in this phase. Keep video material source limited to URL or asset fields; do not add a video binary path.
</action>
<acceptance_criteria>
- Image binary input with MIME `image/png` and buffer `image-bytes` reaches the HTTP body as `data:image/png;base64,<base64 of image-bytes>`.
- Audio binary input with MIME `audio/wav` and buffer `audio-bytes` reaches the HTTP body as `data:audio/wav;base64,<base64 of audio-bytes>`.
- Missing MIME type for image/audio binary produces a user-facing error.
- No new image/audio MIME allowlist appears in `Seedance.node.ts`.
- No `video` binary branch or video binary field is added.
</acceptance_criteria>
</task>
