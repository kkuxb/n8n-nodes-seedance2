# Plan 16-02: Wire binary media metadata into execution and verify full regression

<objective>
Connect the shared Phase 16 validation contract to n8n execution by carrying binary MIME and byte-size metadata from runtime collection into create validation, then prove invalid local media fails before HTTP request while remote URL/asset media remains pass-through.
</objective>

<scope>
In scope:
- Runtime collection changes in `Seedance.node.ts` for multimodal image/audio binary references.
- First/last-frame binary image allowlist alignment with Seedance 2.0 official image MIME support.
- Execute-level tests for binary MIME/size failures and remote URL/asset non-probing.
- Focused and full regression commands.

Out of scope:
- Remote media metadata probing.
- Video binary upload.
- New optional API fields outside Phase 16.
- Lifecycle compatibility audit beyond the regression tests touched here; Phase 17 owns broader lifecycle compatibility.
</scope>

<threat_model>
| ID | Threat | Severity | Mitigation |
|----|--------|----------|------------|
| T-16-05 | Runtime converts binary references to data URLs but drops MIME/size metadata, bypassing shared validation. | high | Populate metadata fields in `collectSeedanceReferenceMaterials()` and add execute-level pre-HTTP rejection tests. |
| T-16-06 | Invalid local binary media triggers an API call before failing. | high | Capture HTTP calls in tests and assert call count remains 0 on local validation errors. |
| T-16-07 | Remote URL/asset validation tries to inspect media and breaks signed URLs. | medium | Use extensionless/signed URL tests and fake context without any remote request helper beyond the create API call. |
| T-16-08 | Execution path introduces unsupported payload fields while refactoring. | medium | Assert captured body excludes `camera_fixed`, `tools`, `web_search`, and `safety_identifier`. |
</threat_model>
