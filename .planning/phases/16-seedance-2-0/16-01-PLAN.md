# Plan 16-01: Add official Seedance 2.0 parameter and local validation contract

<objective>
Establish the shared Phase 16 validation contract: official constants, binary metadata fields, model-specific 1080p rules, deterministic local media validation, and UI/payload tests proving Seedance 2.0 options use strong body fields without exposing unsupported parameters.
</objective>

<scope>
In scope:
- Shared constants for Seedance 2.0 image/audio MIME and size limits plus request-size limit.
- `SeedanceCreateInput` / `SeedanceReferenceMaterialInput` metadata additions needed for binary validation.
- Create validator rules for binary image/audio MIME and size where metadata is available.
- Standard vs Fast `1080p` UI and validator behavior.
- Unit/description tests in `test/createPayload.test.ts`.

Out of scope:
- Runtime population of binary metadata from n8n execution; Plan 16-02 owns this.
- Remote URL/asset probing or metadata parsing.
- New optional capabilities such as `tools.web_search`, `safety_identifier`, `frames`, `draft`, or `service_tier`.
- Phase 17 lifecycle compatibility verification and Phase 18 documentation/UAT.
</scope>

<threat_model>
| ID | Threat | Severity | Mitigation |
|----|--------|----------|------------|
| T-16-01 | URL/asset references are falsely rejected by extension/protocol guesses. | high | Add tests with signed or extensionless URLs and asset IDs that remain valid; prohibit remote probing in must-haves. |
| T-16-02 | Fast model can submit unsupported `1080p` through saved workflow parameters. | high | Add validator test for Fast + `1080p` rejection even if UI hides it. |
| T-16-03 | New metadata fields leak raw media details into `requestSummary`. | high | Add negative summary assertions after metadata extension. |
| T-16-04 | Phase 16 accidentally adds `camera_fixed`, `web_search`, or `safety_identifier`. | medium | Add UI/payload negative tests for unsupported/deferred fields. |
</threat_model>
